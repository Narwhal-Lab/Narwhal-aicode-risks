Summary

Closes the ADR-166 remediation. Implements the server-side tool gate, hardened compose defaults, and CI locks on top of the loopback + bearer-auth work already on this branch.

Design contract (ADR §1.2): the MCP bridge is local-only by default. Public exposure is an explicit opt-in (MCP_BIND_HOST + MCP_AUTH_TOKEN), and the bridge exits ≠0 at boot if the operator opts into public without a token.

Changes

  • Phase 1d + 2a — server-side terminal gate. executeTool() in both bridges denies *terminal_execute* unless MCP_ENABLE_TERMINAL=true. Was previously enforced only in the autopilot flow; the primary /mcp and /mcp/:group paths bypassed it (ADR-166 §3 V3).
  • Phase 2b — MongoDB auth on by default. mongodb runs with --auth; MONGO_INITDB_ROOT_PASSWORD is a hard-required compose variable. chat-ui's MONGODB_URL includes credentials.
  • Phase 2c — read-only bridge rootfs. read_only: true + tmpfs: /tmp. Breaks step 7 of the disclosed PoC (/app/beacon.js write fails EROFS).
  • Phase 3b — CORS allowlist wiring. Both bridges honor MCP_CORS_ORIGIN (comma-separated). Default * for back-compat on loopback.
  • §6 Claude code integration #9 — anti-regression lock. New test-security-lock.js (static-source, 6 checks × 2 bridges) + test-runtime-security.mjs (spawns each bridge, asserts 401/200/TOOL_DISABLED/exit-1 behavior over the wire).
  • CI workflow (.github/workflows/adr-166-mcp-bridge-security.yml) — four jobs on every PR touching bridge/compose/federation: static-source lock, runtime behavior on Node 22, compose defaults, federation bindHost default.

Maintainer decision (2026-06-30): MCP design contract is local-only by
default. Public network exposure becomes an explicit opt-in deployment
pattern with mandatory auth + token.

## Defaults flipped to loopback

- `ruflo/docker-compose.yml`: bridge `3001:3001` → `127.0.0.1:3001:3001`;
  Mongo `27017:27017` → `127.0.0.1:27017:27017`
- Both bridges (`ruflo/src/{ruvocal/,}mcp-bridge/index.js`):
  `app.listen(PORT)` → `app.listen(PORT, BIND_HOST)` with
  `BIND_HOST = process.env.MCP_BIND_HOST || '127.0.0.1'`
- `v3/@claude-flow/plugin-agent-federation/src/bin.ts`:
  default `bindHost` `'0.0.0.0'` → `'127.0.0.1'`

## Optional public deployment pattern

NEW `ruflo/docker-compose.public.yml` — explicit override composition.
Operator must set BOTH `MCP_BIND_HOST=0.0.0.0` AND
`MCP_AUTH_TOKEN=$(openssl rand -base64 32)`, otherwise the bridge exits
non-zero at startup with a FATAL message that includes the token-gen
command.

When `MCP_AUTH_TOKEN` is set (any bind), the new `requireAuth`
middleware enforces `Authorization: Bearer <token>` on all `/mcp*`,
`/chat/completions`, `/autopilot*`, `/mcp-servers` routes using
`timingSafeEqual`. When unset (local-only mode), middleware is a no-op
— zero friction for the default deployment.

## Why this framing

Per the review-thread pushback:
> "If someone has unauthorized access to your environment, you have
>  bigger problems. The MCP is local so unauthorized is the only
>  option."

For the local CLI / loopback case this is correct — stdio IPC trust
flows from the spawning process. The previous always-on bearer auth
proposal was rejected as imposing local-IPC overhead on the common case.

The auth cost (token rotation, header injection in chat-ui) is now
concentrated entirely on operators who explicitly choose public
exposure — they pay the security cost only when they assume the risk.

## ADR-166 amendments (6 surgical edits)

- §1.2 — adds the design-contract clause
- §6 Phase 1 — retitled; 1a now leads with loopback default, 1b is
  fail-closed-on-opt-in, 1c is auth-when-token-set, 1d unchanged
- §6 new "Optional public deployment pattern" subsection with the
  generate-token + compose -f override recipe
- §7 R1/R2 — reframed to acknowledge the UX cost is concentrated in
  the optional path
- §8 — "bind loopback only; skip auth" REJECTED → "loopback default;
  auth for opt-in" ACCEPTED
- §10 — maintainer decision 2026-06-30 cited

2. MCP_ENABLE_TERMINAL gate (1d) — separate commit before merge.
3. Compose-merge smoke test for `ports: []` removal of Mongo host

Completes the ADR-166 remediation. Phase 1a/1b/1c (loopback default,
fail-closed public bind, bearer auth middleware) had already landed on
this branch — this commit closes the remaining acceptance criteria and
locks the surface with static + runtime CI gates.

Adds
- Server-side terminal gate (Phase 1d + 2a). `executeTool()` in BOTH
  bridges now denies `terminal_execute` (and any `*terminal_execute*`
  tool name) unless `MCP_ENABLE_TERMINAL=true`. Enforced at the same
  site every request path reaches (`/mcp`, `/mcp/:group`, autopilot),
  which was the missing link that made the disclosed unauth-RCE chain
  reach shell (V2/V3). Returns `{error, code: "TOOL_DISABLED"}`.
- Startup posture banner. Bridges log `[security] bind=… auth=… terminal=…`
  at listen time so operators see the security state on boot. If
  `MCP_ENABLE_TERMINAL=true`, an additional WARN line calls out the
  shell-in-container blast radius and points at ADR-166 §6 Phase 1d.
- MongoDB auth on by default (Phase 2b). `mongodb` service now runs
  `--auth`; `MONGO_INITDB_ROOT_PASSWORD` is a hard-required compose
  variable (the `${VAR:?…}` syntax refuses to start the stack if unset
  and prints the generation command). `chat-ui`'s MONGODB_URL is
  updated to include the credentials.
- Read-only rootfs on the bridge (Phase 2c). `read_only: true` +
  `tmpfs: /tmp` on the `mcp-bridge` service. Breaks step 7 of the
  disclosed PoC (the `/app/beacon.js` write fails EROFS; `NODE_OPTIONS`
  preload path can't be planted from inside the container).
- CORS allowlist wiring (Phase 3b). Both bridges honor
  `MCP_CORS_ORIGIN` (comma-separated). Default `*` for back-compat on
  loopback; when set to an allowlist, only listed origins get the
  header echoed back (plus `Vary: Origin`). Non-listed origins get
  nothing — browsers block the request.
- Anti-regression static-source lock (Phase §6 #9).
  `ruflo/src/mcp-bridge/test-security-lock.js` — 6 checks × 2 bridges,
  offline, zero-deps. Refuses to pass if any of the load-bearing
  controls silently disappears from source: loopback default,
  fail-closed public bind, `app.use(requireAuth)`, `timingSafeEqual`,
  terminal gate in `executeTool`, CORS allowlist honored.
- Runtime behavioral verification.
  `ruflo/src/mcp-bridge/test-runtime-security.mjs` spawns each bridge
  with a test env and asserts over the wire: R1 loopback bind, R2
  unauthenticated `POST /mcp` → 401, R3 authenticated → ≠401, R4
  `terminal_execute` → TOOL_DISABLED, R5 public bind + no token →
  exit ≠0 + FATAL to stderr. Complements the source-only lock.
- CI workflow `.github/workflows/adr-166-mcp-bridge-security.yml`.
  Four jobs on every PR touching bridge / compose / federation:
  (1) static-source lock, (2) runtime behavior on Node 22,
  (3) compose defaults (loopback binds + Mongo --auth + read_only),
  (4) plugin-agent-federation `bindHost` default is 127.0.0.1.

ADR update
- `ADR-166` status: Proposed → Accepted (Phase 0-3 shipped).
- Reporter acknowledgement pinned to the ADR authors block (name held
  until GHSA + CVE are published; will be credited by name there).
- §9.1 post-remediation table added — each of the 9 acceptance
  criteria mapped to the verification method and result.
