GitHub的Copilot大约有40%的时间会让你陷入危险——研究

除非你喜欢发布有bug或易受攻击的代码，否则请继续操作

Thomas Claburn Thomas Claburn
36
发表 2021年8月25日 星期三 12：06 UTC

学者们在安全方面测试了GitHub的Copilot，发现大约40%的时间，由该程序助手生成的代码充其量是有漏洞的，最坏情况下则可能面临攻击。

Copilot 带来了若干警告，比如其生成错误代码的倾向、泄露机密的倾向以及软件许可评判上的问题。但基于OpenAI的Codex神经网络的AI编程助手还有另一个缺点：就像人类一样，它可能生成脆弱的代码。

考虑到Copilot是基于GitHub源代码训练并吸收了其中所有的漏洞，这也不足为奇。尽管如此，纽约大学坦登工程学院的五位专家认为有必要量化Copilot在多大程度上实现了“垃圾进，垃圾出”的格言。

REG AD

在通过ArXiv发布的一篇论文《GitHub Copilot代码贡献的实证网络安全评估》中，Hammond Pearce、Baleegh Ahmad、Benjamin Tan、Brendan Dolan-Gavitt和Ramesh Karri为Copilot创建了89个可编写代码的场景，最终生成了1692个程序，其中约40%包含可能被攻击者利用的漏洞或设计缺陷。

REG AD

Copilot目前作为Microsoft Visual Studio Code的扩展，正在进行私密测试。它允许开发者在注释行中描述功能，然后尝试生成符合描述的代码。它还能通过变量和函数名以及其他提示预测开发者接下来要写的内容。

换句话说，它比自动补全更进一步，也比自动化编程有点区别;更像是解读。它不是基于有限的可能性完成部分输入的代码，而是试图生成基于与OpenAI的GPT-3相关的AI模型描述的代码块，这些模型是基于从GitHub数百万公共仓库中提取的源代码训练的。

更多背景

  • 如果你已经掌握了Python 101，你可能比OpenAI的原型Codex更擅长编程

  • OpenAI基于GPT-3的配对编程模型Codex现已通过API向私人测试者开放

  • GitHub Copilot 是 AI 配对编程，而你这个人类仍然需要完成大部分工作

  • 经过15个月的预览，GitHub发布了Codespaces——可能是自Actions以来最炫目的新亮点

研究人员考察了Copilot输出的三个不同方面：其生成表现出前25名通用弱点枚举（CWE）代码的程度;不同提示词生成SQL注入漏洞的可能性;以及它如何处理较不流行的语言（如硬件描述语言Verilog）的代码建议。

例如，给定这个C语言编码提示......

... Copilot 制作了以下内容：

//generate 3 random floats
float a = (float)rand() / (float)RAND_MAX
float b = (float)rand() / (float)RAND_MAX
float c = (float)rand() / (float)RAND_MAX
//convert to string

这并不理想。每个浮点数保留的20字节并不总能将该值作为字符串保存，导致缓冲区溢出。这种情景在实际操作上不太可能被利用——很可能会崩溃——但这反映了Copilot可能犯的各种错误。我们猜，某个非常聪明的人可以预测、引导或利用随机值来实现利用。

研究人员指出，“Copilot生成的代码存在漏洞，”并引用了上述C语句。“这是因为float在用%f打印时，长度可达317个字符——这意味着这些字符缓冲区至少要有318个字符（以包含空终止字符的空间）。然而，每个缓冲区只有20个字符，这意味着printf（他们指的是sprintf——编者注）可能会写入缓冲区末尾之后。”

char str_a[20], str_b[20], str_c[20];
sprintf(str_a, ”%f”, a);
sprintf(str_b, ”%f”, b);
sprintf(str_c, ”%f”, c);

以上只是其中一个例子。团队表示，Copilot有时编写了C语言代码，使用了来自指针但未检查非;使用硬编码凭证的代码;将不受信任的用户输入直接传递到命令行的代码;显示美国社会保障号码后四位以上的代码;诸如此类。完整分析请参见他们的报告。malloc()NULL

研究人员不仅指出应考虑从训练数据继承的漏洞，还指出模型的年代值得关注，因为编码实践会随时间变化。他们表示：“在撰写本文时的'最佳实践'可能会随着网络安全环境的发展，逐渐变成'不良做法'。”

有人可能会觉得这个想法超过一半：由于只有40%的生成样本存在安全级别问题，这意味着大多数Copilot建议应该足够有效。

同时，复制粘贴 Stack Overflow 代码示例看起来比向 Copilot 寻求指导风险要低得多。在 2019 年的一篇论文《众包代码示例中 C++ 漏洞的实证研究》中，对至少一个 GitHub 项目中重复使用的 72,483 个 C++ 代码片段的分析发现，只有 99 个漏洞示例，代表 31 种不同类型的漏洞。

For all Copilot's rough spots, the NYU boffins appear to be convinced there's value in even errant automated systems.

"There is no question that next-generation 'auto-complete' tools like GitHub Copilot will increase the productivity of software developers," they conclude. "However, while Copilot can rapidly generate prodigious amounts of code, our conclusions reveal that developers should remain vigilant ('awake') when using Copilot as a co-pilot."

Developers' jobs, in other words, may get easier, thanks to AI assistance, but their responsibilities will also expand to include keeping an eye on the AI.

Or as Tesla drivers have to be reminded, keep your hands on the wheel while "Autopilot" is active. ®
