Summary

Fixes an arbitrary local file read in consult_gemini_with_files inline mode (CWE-22 / CWE-200). A caller-supplied files entry was read with no working-directory confinement and its contents forwarded to the Gemini CLI; since the caller also controls query, the file could be echoed back through the round-trip.

The at_command mode already confined paths — inline mode was missing the same guard.

Changes

  • _resolve_path: resolve symlinks for both the root and the candidate, then confine via relative_to(root). rel_path is None for anything escaping the root (absolute path outside, .. traversal, or symlink escape). This hardens both modes consistently.
  • _prepare_inline_payload: skip entries that resolve outside the working directory with a Skipped file outside working directory warning (the guard at_command already had) — no read.
  • Regression tests: absolute-outside, .. traversal, and symlink escape are rejected (content not forwarded); absolute-inside still works.
  • CHANGELOG + tool docstring updated; version bumped to 1.3.1.

Behavior change

at_command mode now also rejects symlinks that resolve outside the working directory (previously a lexical-only check let them through).

Testing

pytest — 38 passed.

Reported privately by Zhihao Zhang (WPI).
